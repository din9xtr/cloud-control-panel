# Development

Go 1.27, Node 24, pnpm 10.

```bash
CLOUD_DATA_DIR=data go run ./cmd/cloud
cd web && pnpm install && pnpm dev
```

The Vite dev server on `:5173` proxies the API to `:8080`. Open it and create an
account on the setup page.

Every change must leave these green:

```bash
go test -race ./...
golangci-lint run ./...
cd web && pnpm test && pnpm lint && pnpm typecheck
```

The API types used by the frontend are generated from [`api/openapi.yaml`](../api/openapi.yaml)
with `pnpm gen`; change the contract first, never the generated file. Database changes are
new files in `internal/sqlite/migrations`.

Every API change must also work in the web interface, CLI and MCP server. The CLI
and MCP catalog is derived from the embedded contract; verify argument schemas,
transfer behavior and client documentation alongside the web workflow.

```bash
go build -o cloud ./cmd/cloud
./cloud cli help
./cloud mcp --help
go test -race ./internal/remote ./internal/command ./internal/httpapi
```

See [CLI](cli.md) for terminal examples and [MCP](mcp.md) for agent configuration.

## Release binaries

Run `python3 scripts/release.py v0.2.0` with Python 3.11+, Go, Node and pnpm
installed. The script installs locked frontend dependencies, builds the embedded
SPA, cross-compiles without CGO for Linux/macOS/Windows on amd64 and arm64, and
creates six archives with `SHA256SUMS` under `bin/releases/v0.2.0/`.
Each version needs release notes at `docs/releases/VERSION.md`.

Run the manual **Release checks** GitHub Actions workflow before publication
to test on native Linux, macOS and Windows runners. Cross-compilation alone
does not verify runtime behavior on another OS. Executables are unsigned;
release archives are attached to the matching Git tag.

## One contract for every client

`api/openapi.yaml` owns HTTP operations, request/response schemas, CLI aliases
(`x-cli-aliases`) and local transfer argument schemas (`x-client-operations`).
Frontend types are generated by `pnpm gen`; CLI and MCP read the same embedded
contract at runtime. Local transfer implementations remain in `internal/remote`.
Do not add a separate command list or argument schema in a client adapter.

After changing the contract:

```bash
cd web && pnpm gen
cd ..
go run ./cmd/cloud-docs
go run ./cmd/cloud-docs --check
go test -race ./...
```

`docs/commands.md` is generated and its freshness is checked by Go tests. Keep
connection instructions in `docs/clients.md`, terminal examples in `docs/cli.md`
and MCP transport details in `docs/mcp.md`.
