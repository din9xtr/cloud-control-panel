# Cloud v0.2.0

Self-hosted file storage with a web control panel, CLI and MCP server.
Resumable uploads, shared folders and file requests — all in one Go binary.

## What's new

- Replace the PHP application with a Go server, embedded React interface,
  SQLite metadata and local file storage.
- Manage files and folders, rename and move entries, search, download ZIP
  archives, preview files, restore trash and configure automatic retention.
- Upload large files with tus resume support; upload directories with nesting
  and empty folders preserved.
- Share files and browsable folders through expiring, revocable links.
- Collect files through upload-only folder links without exposing existing
  contents or overwriting existing files.
- View storage quota, disk space and usage by folder and file type.
- Set up the first account, change credentials and revoke active sessions.
- Automate the same HTTP API through the remote CLI or MCP server over stdio,
  with OpenAPI-derived commands and tool schemas.
- Confine MCP file transfers to an explicit local directory and optionally
  expose only read operations.
- Protect storage with os.Root, hashed session tokens, strict CSP,
  cross-origin protection, bounded expensive operations and request limits.
- Run in a non-root container with a read-only filesystem and persistent data.
- Add native Windows disk-space reporting, Windows DPAPI session encryption
  and consistent JavaScript/CSS content types across operating systems.

Node.js, PHP or database installation is required.

## Start the server

Extract the archive into a writable directory, then run on Linux/macOS:

```sh
./cloud serve
```

On Windows, in PowerShell:

```powershell
.\cloud.exe serve
```

Open `http://localhost:8080` and create your account. The default data directory
is `./data`, relative to the working directory. Keep this directory persistent.
Use `CLOUD_DATA_DIR` to choose a different location and `CLOUD_ADDR` to change
the listening address. Use an HTTPS reverse proxy for remote access.

The same executable also provides `cloud cli help` and `cloud mcp --help`.
On Windows, CLI sessions are encrypted for the current Windows account;
on Linux/macOS, session files require private Unix permissions (`0600`).

## Upgrading from v0.1.0

Back up the database and files before upgrading. Stop the old service and point
`CLOUD_DB_PATH` at the existing SQLite database and `CLOUD_STORAGE_DIR` at the
existing storage root. The new `./data` defaults may differ from your old layout.
Startup migrations
preserve legacy accounts and database tables. Review the new configuration:
PHP/Caddy deployment files and old environment variables have been replaced.
Do not run both versions against the same data directory. To roll back, stop
the new server and restore the backup with the old deployment.

See [connection setup](https://github.com/din9xtr/cloud-control-panel/blob/v0.2.0/docs/clients.md),
